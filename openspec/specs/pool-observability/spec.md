# pool-observability Specification

## Purpose

Наблюдение за пулом через HTTP: что сервис сообщает о своём состоянии, как получить сведения о
применённой конфигурации и как измерить влияние размера пула на обслуживание запросов.

## Requirements

### Requirement: Состояние пула доступно через HTTP

Сервис SHALL предоставлять наблюдаемое состояние пула, включающее текущий размер и минимум,
число открытых, занятых и свободных соединений, число потоков, ожидающих соединение, признак
закрытия, момент создания и последнего изменения, причину последнего изменения и счётчики
изменений размера и пересозданий.

#### Scenario: Наблюдение в покое

- **WHEN** состояние пула запрошено через API
- **THEN** ответ содержит согласованный набор полей, отражающий текущее состояние пула

### Requirement: Применённая конфигурация доступна через HTTP

Сервис SHALL отдавать через API конфигурацию, применённую к пулу в данный момент, то есть
результат слияния значений из etcd, локальных умолчаний и проверки. Скрытые значения
SHALL NOT передаваться в открытом виде.

#### Scenario: Пароль не раскрывается

- **WHEN** состояние пула запрошено через API
- **THEN** значение пароля в ответе заменено маской, а не передано как есть

### Requirement: Состояние источника конфигурации доступно через HTTP

Сервис SHALL предоставлять через API состояние источника конфигурации отдельно от состояния
пула, включая признак включённости, признак активности подписки, наблюдаемые значения ключей,
текущую ревизию, время последнего события, число применений, исход последнего применения,
непрочитанные значения и последнюю ошибку. Состояние SHALL включать путь конфигурации, по
которому работает источник. Когда источник включён, а конфигурация по его пути ещё не получена,
состояние SHALL сообщать причину неготовности отдельно от последней ошибки. Путь конфигурации
SHALL NOT раскрываться, когда источник выключен.

#### Scenario: Отключённый источник не путают со сбоем

- **WHEN** источник конфигурации отключён
- **THEN** в статусе видно, что он отключён, в отличие от ситуации, когда источник включён,
  но подписка не активна

#### Scenario: Пустой снимок после старта

- **WHEN** сервис поднялся, а событий ещё не было
- **THEN** время последнего события равно нулю, что вместе с признаком активности подписки
  позволяет отличить отсутствие событий от обрыва

#### Scenario: Путь конфигурации виден в статусе

- **WHEN** состояние источника запрошено через API
- **THEN** ответ содержит путь конфигурации, по которому источник читает ключи

#### Scenario: Причина неготовности видна до получения конфигурации

- **WHEN** источник включён, но конфигурация по его пути ещё не получена
- **THEN** в состоянии источника видна причина неготовности, отличная от последней ошибки
  подписки

#### Scenario: Источник выключен, путь не раскрывается

- **WHEN** источник конфигурации выключен
- **THEN** в состоянии источника путь конфигурации отсутствует

### Requirement: Число сессий базы данных доступно для наблюдения

Сервис SHALL сообщать число сессий, принадлежащих пулу, с разделением на активные и свободные.
Если это невозможно, ответ SHALL содержать причину вместо молчаливого отсутствия данных.

#### Scenario: Пул занят, интроспекция невозможна

- **WHEN** у пула нет свободных соединений
- **THEN** вместо чисел возвращается объяснение, что свободных соединений нет, и наблюдение
  не усугубляет очередь

### Requirement: Наблюдение не занимает соединение насыщенного пула

Запрос наблюдения SHALL NOT удерживать соединение дольше заданного таймаута, чтобы при
насыщенном пуле он не усугублял очередь.

#### Scenario: Пул полностью насыщен

- **WHEN** наблюдение выполняется при полностью занятом пуле
- **THEN** запрос наблюдения завершается по своему таймауту, не удерживая соединение дольше
  отведённого

### Requirement: Нагрузочная точка измеряет влияние размера пула

Сервис SHALL предоставлять точку, выполняющую реальный запрос к базе с удержанием соединения
заданное время. Ответ SHALL содержать общее время, время в базе, время ожидания соединения и
снимок состояния пула на момент ответа.

#### Scenario: Очередь за соединение

- **WHEN** размер пула мал, а число одновременных запросов велико
- **THEN** в ответах время ожидания соединения ненулевое и растёт вместе с нагрузкой

#### Scenario: Недопустимое время удержания

- **WHEN** запрошено время удержания вне допустимого диапазона
- **THEN** сервис отвечает отказом с указанием допустимого диапазона и не выполняет запрос

#### Scenario: Не удалось получить соединение

- **WHEN** соединение получить не удалось в пределах таймаута
- **THEN** сервис отвечает ошибкой доступности с причиной и не возвращает снимок пула
