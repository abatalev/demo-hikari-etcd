# Spec Delta

## ADDED Requirements

### Requirement: Один активный провизор на сервис

Для каждого сервиса `{root}/services/{service}` провижинирование конфигурации SHALL выполнять
ровно один экземпляр провизора из числа развёрнутых. Остальные экземпляры SHALL при этом не
производить провижинирование, очистку осиротевших префиксов и сверку конфигурации.

#### Scenario: Несколько провизоров, один активен

- **WHEN** развёрнуто несколько экземпляров провизора и в дереве есть живые сервисы
- **THEN** для каждого сервиса провижинирование выполняет ровно один экземпляр, остальные
  бездействуют

#### Scenario: Лидер падает, запасной перехватывает

- **WHEN** экземпляр, выполняющий провижинирование сервиса, перестаёт работать
- **THEN** в течение ограниченного времени провижинирование продолжает другой экземпляр,
  начинающий с полной сверки

#### Scenario: Штатная остановка лидера

- **WHEN** активный экземпляр останавливается штатно
- **THEN** его место занимает другой экземпляр без ожидания истечения срока аренды

#### Scenario: Вернувшийся лидер не раздваивает работу

- **WHEN** экземпляр, ранее выполнявший провижинирование, возвращается после остановки
- **THEN** провижинирование продолжает другой экземпляр, а вернувшийся не вмешивается —
  активен по-прежнему ровно один

### Requirement: Набор сервисов определяется из дерева

Экземпляр провизора SHALL сам определять, за какие сервисы участвовать в выборе лидера, по
живым узлам дерева `{root}/services/`. Список сервисов SHALL NOT конфигурироваться. Сервис без
живых узлов SHALL NOT иметь лидера. При появлении первого узла сервиса лидер SHALL быть выбран
без перезапуска провизора; при исчезновении последнего узла выбор лидера за этот сервис SHALL
завершиться.

#### Scenario: Новый сервис появляется на работающем стенде

- **WHEN** в дереве появляется узел нового сервиса
- **THEN** для этого сервиса выбирается лидер, и его конфигурация провижинируется без
  перезапуска провизора

#### Scenario: Сервис без живых узлов

- **WHEN** в сервисе нет ни одного живого узла
- **THEN** за этот сервис выборы не ведутся, лидера нет

#### Scenario: Последний узел сервиса исчезает

- **WHEN** исчезает последний живой узел сервиса
- **THEN** выбор лидера за этот сервис завершается

### Requirement: Переживание обрывов хранилища при выборах

При недоступности хранилища экземпляры провизора SHALL продолжать работу, повторяя попытки
выбора лидера с возрастающей паузой. При возврате хранилища провизор SHALL восстановить
провижинирование без перезапуска: для каждого живого сервиса выбирается ровно один лидер,
начинающий с полной сверки.

#### Scenario: Хранилище недоступно на старте

- **WHEN** провизор запускается при недоступном etcd
- **THEN** процесс продолжает работать и после возврата etctd включается в выборы лидера

#### Scenario: Обрыв во время работы

- **WHEN** etcd был недоступен во время работы провизора, а затем снова ответил
- **THEN** провижинирование возобновляется: для каждого живого сервиса выбирается лидер и
  инвариант «ключи ⟺ живой узел» восстанавливается
