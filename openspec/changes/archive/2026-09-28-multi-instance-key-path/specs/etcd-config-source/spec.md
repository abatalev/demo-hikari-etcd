# Spec Delta

## ADDED Requirements

### Requirement: Путь конфигурации включает идентичность экземпляра

Путь ключей конфигурации SHALL содержать сегменты, различающие экземпляры: имя сервиса, группу
и имя экземпляра. Ключи под путём одного экземпляра SHALL применяться только этим экземпляром и
SHALL NOT влиять на другие экземпляры.

#### Scenario: Два экземпляра одной группы

- **WHEN** двум экземплярам одной группы заданы разные размеры пула
- **THEN** каждый экземпляр применяет свой размер и не изменяет пул другого

#### Scenario: Одинаковое имя экземпляра в разных группах

- **WHEN** в разных группах существуют экземпляры с одинаковым именем
- **THEN** конфигурация одного из них не влияет на другого

### Requirement: Некорректный путь конфигурации отвергается на старте

При включённом источнике конфигурации сегменты пути SHALL быть непустыми и SHALL NOT содержать
разделителя пути. Нарушение SHALL прекращать запуск с сообщением, называющим проблемный сегмент.

#### Scenario: Сегмент пути не задан

- **WHEN** экземпляр запущен без значения группы или имени экземпляра
- **THEN** запуск прекращается, в сообщении назван отсутствующий сегмент

#### Scenario: Сегмент пути содержит разделитель

- **WHEN** имя экземпляра содержит символ разделителя пути
- **THEN** запуск прекращается, в сообщении назван проблемный сегмент

#### Scenario: Источник конфигурации выключен

- **WHEN** экземпляр запущен с выключенным источником конфигурации
- **THEN** некорректный путь не препятствует запуску

### Requirement: Пустой префикс не остаётся незамеченным

Снимок префикса, не содержащий ни одного ключа, SHALL сопровождаться предупреждением, из которого
понятен путь. Состояние источника SHALL показывать, что конфигурация по этому пути не получена.

#### Scenario: В пути нет ни одного ключа

- **WHEN** снимок пути конфигурации не содержит ключей
- **THEN** в журнал выводится предупреждение с указанием пути, и из состояния источника видно,
  что конфигурация не получена

## MODIFIED Requirements

### Requirement: Недоступность хранилища не влияет на обслуживание

При недоступности etcd сервис SHALL НЕ падать и SHALL оставаться запущенным, продолжая попытки
восстановить подписку. Если конфигурация уже была применена, сервис SHALL продолжать обслуживать
запросы на последней применённой конфигурации. Если конфигурация ещё не была применена, сервис
SHALL оставаться запущенным, но SHALL NOT принимать запросы обслуживания до её получения.

#### Scenario: etcd остановлен во время работы

- **WHEN** etcd становится недоступен при работающем сервисе
- **THEN** пул продолжает обслуживать запросы с последней применённой конфигурацией, в статусе
  видно, что подписка не активна

#### Scenario: etcd недоступен на старте

- **WHEN** сервис стартует при недоступном etcd
- **THEN** сервис поднимается на локальных значениях по умолчанию, остаётся запущенным, но не
  принимает запросы обслуживания и становится готовым самостоятельно, когда etcd возвращается
