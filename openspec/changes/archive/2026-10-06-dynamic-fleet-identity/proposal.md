# Proposal: dynamic-fleet-identity

## Why

Состав стенда и идентичность инстансов задаются статическим перечнем `ETCD_INSTANCES` в `.env`
(восемь кортежей «сервис|группа|инстанс|порт»), из которого выводятся блоки compose, хост-порты,
бэкенды балансировщика и правила молчания, а соглашение об именах (`service-…`) отдельно прошито
в отбор сессий флота в правиле по потолку и в панелях. Целевое развёртывание — Kubernetes, где
состав динамичен: имя инстанса приходит из имени пода, число — из числа реплик, обнаружение
бэкендов — из меток. Стенд должен вести себя так же: идентичность из окружения, состав из
масштабирования, бэкенды из меток — без второй копии состава и без соглашения об именах.

## What Changes

- **Идентичность инстанса из окружения развёртывания.** Дефолт имени инстанса —
  `ETCD_INSTANCE → POD_NAME → HOSTNAME`, группы — `ETCD_GROUP → POD_NAMESPACE`. Имя сессии пула
  (`POOL_NAME`) следует за именем инстанса. **BREAKING**: статические имена инстансов в
  конфигурации стенда больше не используются.
- **Состав вместо перечня.** Восемь блоков с именами и хост-портами заменяются четырьмя
  сервисами-группами, каждый поднимается командой масштабирования (`--scale`, значение — как
  число реплик). Перечень `ETCD_INSTANCES` и его фолбэк-дефолты удаляются. **BREAKING**: прямое
  обращение к конкретному инстансу по хост-порту недоступно; перечни стенда строятся из живых
  источников (развёрнутые контейнеры, узлы регистрации, метрики).
- **Балансировщик на метках.** Файловый провайдер (`traefik/dynamic/fleet.yml`,
  `scripts/balancers.py`, сверка `check-balancers`) заменяется docker-провайдером с метками
  контейнеров; распределителю доступен `docker.sock` (ro). Новые и удалённые реплики попадают в
  состав без правки настройки. **BREAKING**: удаляются `fleet.yml`, `scripts/balancers.py` и
  сверка `check-balancers`.
- **Наблюдение без соглашения об именах.** Отбор сессий пула в правиле по потолку и в панелях
  определяется именами пулов из метрик инстансов, а не шаблоном `service-.+`; правило работает
  при любых именах. Правила молчания и сверки состава строятся из живого состава, а не из
  файла-перечня.
- **Команды стенда работают с живым составом.** Перечни для команд (`pool`, `budget`,
  `sessions`, ручные правки) берутся из узлов регистрации и развёрнутых контейнеров; готовность
  и размер пула — из метрик, без HTTP-обращения к инстансам. Нагрузчик зависит от группы, а не
  от конкретного инстанса.

## Capabilities

- **Modified Capabilities**:
  - `demo-stand` — состав из масштабирования групп; распределитель на метках; сверки и правила
    молчания из живого состава; отбор сессий без шаблона имён; команды против живого состава.
  - `instance-registration` — имя инстанса и группы из окружения развёртывания; имя сессии пула
    равно имени инстанса.

## Impact

- **service**: дефолты идентичности в `application.yml`, `POOL_NAME` следует за именем инстанса;
  юнит-тесты чистых функций идентичности.
- **compose**: четыре сервиса-группы с `--scale`, удаление портов и имён инстансов; `lb` на
  docker-провайдере с `docker.sock` (ro) и метками.
- **Makefile/scripts**: перечисление из `docker compose ps` и etcd-дерева; удаление
  `scripts/balancers.py` и `check-balancers`; `scripts/wait-ready.sh` только по точкам входа;
  `scripts/pool-all.py` — состояние из метрик.
- **prometheus/grafana**: отбор сессий join-ом по метрикам пула; правила молчания из живого
  состава; `$pool_app` без шаблона имён.
- **docs/README**: описание состава, имён и команд; `docs/experiments.md` — пересъёмка с
  именами из окружения.
