# Proposal

## Why

Сужение etcd до размера пула (изменение `etcd-scope-is-pool-size`, дельта
`2026-10-05`) провело по коду, но спеки двух capability синхронизированы не полностью:
`config-provisioner` не была тронута вовсе и до сих пор требует стартовый ключ
`connectionTimeoutMs`, которого нет и не будет, а `config-validation` описывает «локальное
значение размера пула» — рычаг `pool.db.maximum-pool-size`, удалённый следующим рефакторингом
(коммит `1885ad8`). Поведение уже соответствует цели; спеки отстали от него.

## What Changes

Только тексты спек — код не меняется, поведение не изменяется:

- **config-provisioner**:
  - требование «Появление узла порождает стартовые ключи»: стартового таймаута
    `connectionTimeoutMs` больше нет, провижер обеспечивает в пути инстанса только
    `maximumPoolSize` — долю бюджета; сценарии «Новый инстанс зарегистрировался» и «Повторная
    регистрация уже настроенного инстанса» переписаны под единственный ключ;
  - требование «События конфигурации игнорируются»: `connectionTimeoutMs` исключён из
    перечисления неприкасаемых ключей — вне `maximumPoolSize` неприкасаемы любые ключи пути
    (в том числе добавленные оператором).
- **config-validation**:
  - требование «Конфигурация из etcd имеет приоритет над локальными значениями»: снята
    формулировка «локальное значение размера пула» — локального размера нет вовсе, при
    отсутствии ключа размера пул закрыт (целевой ноль), а не получает локальный дефолт;
  - требование «Числовые параметры ограничены допустимыми диапазонами»: размер задаётся только
    из хранилища конфигурации, локального размера не существует; сценарий «Локальный размер
    пула равен нулю» заменён на «Локального размера пула нет»;
  - требование «Нечитаемое значение игнорируется только для своего ключа»: битый ключ не
    подменяется локальным значением по умолчанию — для размера дефолта не существует, ключ
    остаётся неприменённым; сценарий уточнён.

## Capabilities

### New Capabilities

_(нет)_

### Modified Capabilities

- `config-provisioner`: стартовых ключей таймаутов нет, путь порождает только долю бюджета
  `maximumPoolSize`; перечень неприкасаемых ключей без `connectionTimeoutMs`.
- `config-validation`: локального значения размера пула не существует — отсутствие ключа размера
  означает закрытый пул, битый размер не подменяется дефолтом.

## Impact

- Только `openspec/specs/config-provisioner/spec.md` и `openspec/specs/config-validation/spec.md`
  (`## MODIFIED Requirements`). Дельта описывает уже применяемое поведение.
- Код, API, зависимости, compose и документация стенда не затрагиваются.
- Проверка: `openspec validate --all`; сверка формулировок с кодом (`EtcdKeys`, `PoolSize`,
  `PoolSizeDistribution`) и со стендом (в пути инстанса ровно один ключ — `maximumPoolSize`;
  локального размера нет: пул появляется только из конфигурации etcd).
