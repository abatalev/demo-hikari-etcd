# Design

## Context

См. proposal.md — мотивация. `docker-compose.yml` (486 строк) держит восемь YAML-якорей, из
которых три мёртвые или однократные, а инстансная цепочка собирается из трёх уровней слива.
Изменение — структурный рефакторинг без изменения поведения: плоские блоки, четыре сервиса
константами, правки формулировок в документации. Спеки не трогаются (`skip_specs: true`).

## Goals / Non-Goals

Цели:
- Один файл `docker-compose.yml` без `<<:`, `&`, `*` — каждый из 20 сервисов самодостаточен.
- `etcd`, `otel-collector`, `prometheus`, `grafana` — константами, без `${VAR}` для портов.
- Поведение стенда идентично: `docker compose config` до рефакторинга совпадает с после
  (допустимое расхождение — только четыре зашитых хост-порта).

Не-цели:
- Не менять топологию стенда: состав сервисов, имена, `--scale`/`REPLICAS`, тома, метки,
  healthcheck'и, цепочки `depends_on` остаются как есть.
- Не вводить генераторы конфигурации, `env_file` и дополнительные файлы.
- Не менять спецификации: внешнее поведение не изменяется.

## Decisions

1. **Плоские блоки с повторением env вместо `env_file`.** Общие 12 переменных инстансного env
   повторяются в каждом из четырёх блоков групп целиком. Выбор: «один файл» важнее, чем
   экономия строк; расхождение при будущей правке видно в одном файле при чтении.
   Альтернативы, рассмотренные и отклонённые: `env_file` с `service-common.env` (убирает
   повторение, но добавляет соседний файл), сохранение якорей (от них уходим по требованию).

2. **Четыре сервиса — константами.** Хост-порты зашиваются: etcd 2379/2380,
   otel-collector 4318/9464, prometheus 9090, grafana 3000. Из `.env.example` удаляются
   `ETCD_PORT`, `ETCD_PEER_PORT`, `OTLP_PORT`, `OTEL_METRICS_PORT`, `PROM_PORT`, `GRAFANA_PORT`.
   `Makefile` и `scripts/wait-ready.sh` не правятся: их дефолты уже равны зашитым значениям,
   поэтому `make up`, `make pool`, `scripts/wait-ready.sh` работают без изменений.

3. **Гарантия «поведение не изменилось» — сравнением `docker compose config`.** До правки
   снимается референс конфигурации (`docker compose config` с текущего окружения), после —
   заново; diff допустим только в четырёх host-портах (строки `ports:` у etcd, otel-collector,
   prometheus, grafana) — там, где `:2379`/`:2380`/`:4318`/`:9464`/`:9090`/`:3000` до были
   переменными с дефолтами. Механическая сверка заменяет спеки как контракт: поведение задаётся
   конфигурацией, и её изоморфность доказывает неизменность поведенческого контракта.

4. **Внутренние адреса не трогаются.** Все адреса внутри сети compose (`http://etcd:2379`,
   `DB_URL`, точки сигналов `http://otel-collector:4318/...`) не зависят от хост-портов и
   остаются прежними.

## Risks / Trade-offs

- [Потеря структурной гарантии «у инстанса не может оказаться база чужого сервиса»] →
  Mitigation: якоря `x-service-a`/`x-service-b` задавали разделение принудительно; в плоском
  файле согласованность `SERVICE_NAME`/`DB_URL`/меток `web-a`/`web-b` несёт каждый блок.
  Изоморфность `docker compose config` до/после доказывает, что рефакторинг ничего не сломал,
  а формулировки AGENTS.md/README/docs фиксируют новое соглашение явно.
- [Расхождение четырёх инстансных блоков при будущих правках] → Принято как плата за
  читаемость: файл один, повторённый env виден рядом, расхождение обнаруживается при чтении
  и глазной сверкой в `make up`/`make test` (состав, правила молчания, сверки состава).
- [Остаточный `.env` пользователей с нестандартными портами] → После рефакторинга compose
  перестанет читать удалённые переменные, а Makefile продолжит читать `.env`; при нестандартных
  значениях в `.env` расхождение обнаружится сравнением `docker compose config` до/после и не
  повлияет на дефолтный стенд (дефолты совпадают).

## Migration Plan

1. До правки: `docker compose config` сохранить в референсный файл.
2. Переписать `docker-compose.yml` (плоские блоки, константы, встроенный `etcdctl`).
3. `docker compose config` после; diff с референсом — допустимы только строки четырёх
   хост-портов.
4. Правки формулировок в `AGENTS.md`, `README.md`, `docs/operations.md`; удаление шести
   переменных из `.env.example`.
5. `make up` на живом стенде, затем `make test`, `make check-silence`, `make check-instances`.
6. Откат: `git checkout` прежнего `docker-compose.yml` — поведение идентично, откат тривиален.
