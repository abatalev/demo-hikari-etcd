# Design

## Context

См. proposal.md. В трёх независимых Maven-проектах уже стоит SpotBugs 4.9.3.0
(`threshold=Medium`, `effort=Max`) с гейтом на `verify`; `make test` гоняет `mvn -B -q verify`
для service и provisioner, loadgen вне цикла (его pom подключён к `verify`, плагин сработает при
явном `mvn verify`).

Версии (проверено по pom на Maven Central и фактическим прогоном):

- `findsecbugs-plugin` 1.14.0 — собран против `spotbugs` 4.8.6 (root-pom, scope `provided`);
  плагин-детектор совместим с нашим core 4.9.3.0, апгрейд SpotBugs не нужен.
- `maven-pmd-plugin` 3.28.0 — тянет PMD 7.17.0 по умолчанию (`<pmdVersion>7.17.0</pmdVersion>`),
  уже лежал в локальном `.m2`.
- В PMD 7 правила неиспользуемого кода разложены по категориям иначе, чем в 6:
  `UnusedLocalVariable` и `UnusedPrivateField` — в `category/java/bestpractices.xml`,
  `UnusedImports` как отдельного правила **нет** — он объединён с `UnnecessaryImport`
  (codestyle, `typeResolution=true`).
- Формат ruleset для PMD 7 — прежний `ruleset_2_0_0.xsd` (схема осталась в core 7.17.0).

Одноразовый прогон анализа до правок: service — 1 находка findsecbugs (`XSS_SERVLET`) и 6 PMD
(1 мёртвое поле, 1 лишний импорт, 4 «неиспользуемые» `try`-ресурса), provisioner — 4 PMD
(1 «неиспользуемый» `watcher`, 3 `try`-ресурса), loadgen — 0.

## Goals / Non-Goals

**Goals:**
- Детекторы безопасности findsecbugs в гейте p1–p2 всех трёх проектов.
- Гейт неиспользуемого кода (локальные переменные, private-поля, импорты) в `make test`.
- Все находки разобраны: реальные — исправлены, намеренные — подавлены на месте с обоснованием,
  без `excludeFilterFile` и классовых подавлений на здоровые классы (как в spotbugs-чейндже).

**Non-Goals:**
- Апгрейд SpotBugs 4.9.3.0: не нужен, совместимость findsecbugs 1.14.0 проверена фактическим
  прогоном (детектор работал, `BugInstance size is 0` после подавления).
- `UnusedFormalParameter` (шум на Spring-обвязке), `UnusedAssignment` (строже, ложные срабатывания
  на счётчиках циклов) — вне набора правил.
- Анализ тестового кода: и spotbugs, и PMD по умолчанию смотрят `src/main` (`includeTests=false`).
- Правки `docs/`, docker-сборка (оба гола — на `verify`, образы собираются `package`), смена
  версии плагинов после привязки — вне объёма.

## Decisions

**Подключение findsecbugs.** Детектор кладётся внутрь конфигурации существующего
`spotbugs-maven-plugin` (`<plugins><plugin>findsecbugs-plugin 1.14.0</plugin></plugins>`); гейт
остаётся тем же (`threshold=Medium`, `effort=Max`, `failOnError=true`), новые баг-типы безопас-
ности попадают в отчёт на общих основаниях.

**`XSS_SERVLET` в `TrafficGateFilter:49`.** findsecbugs помечает любой `PrintWriter.write(String)`
в сервлете как «reflected XSS». Здесь пишется JSON: `Map.of("ok", false, "error", reason)`, где
`reason` — внутренняя причина из закрытого набора (`NotReadyCause.describe`), не пользовательский
ввод, а контент-тип — `application/json`, а не `text/html`. Уязвимости нет. Подавление —
method-level `@SuppressFBWarnings("XSS_SERVLET")` с обоснованием (как остальные подавления
проекта); проверено: `US_USELESS_SUPPRESSION_ON_CLASS` не возникает (аннотация на методе
сопоставляется с находкой внутри метода).

**Ruleset PMD — один общий файл `pmd-ruleset.xml` в корне репозитория.** Проекты независимы
(корневого агрегатора нет), но лежат рядом; `../pmd-ruleset.xml` из каждого проекта разрешается
в один файл — третьей копии набора правил не появляется. Набор: `UnusedLocalVariable`,
`UnusedPrivateField`, `UnnecessaryImport`. `minimumPriority` не трогается (5 — все правила набора,
включая `UnnecessaryImport` приоритета 4 и unused-правила приоритета 3).

**Разбор находок — исправить (реальные проблемы).**

- `EtcdConfigWorker.spans` — мёртвое поле: присваивается в конструкторе и нигде не читается.
  Пережиток разделения фасада (`7d598ab`): применение конфигурации пишет свои spans внутри
  `ManagedPool` (у него собственное поле `spans`), а события воркера не регистрируются.
  Fix: удалить поле, параметр конструктора и аргумент в `EtcdPoolConfigSource` (тест на
  конструктор воркера отсутствует — проверено grep'ом). Поведение не меняется: значение параметра
  раньше игнорировалось.
- Лишние импорты: `PoolGauges` — `org.slf4j.Logger` (поле `log` пишется FQN-типом
  `org.slf4j.Logger`, `LoggerFactory` по-прежнему через импорт); `EtcdConfigWorker` —
  `MechanismSpans` (осиротел после удаления поля).

**Разбор находок — документированный фильтр правила.** PMD `UnusedLocalVariable` считает
«неиспользуемой» переменную `try`-ресурса, которая не упоминается в теле (watch-`Watcher`,
`Event`, `Scope` от `span.makeCurrent()`), — классический ложный прогон: ресурс существует
только ради неявного `close()`, ссылка в теле невозможна без мусора. Правило документирует
фильтр: «переменные, чьи имена начинаются с `ignored` или `unused`, исключаются». Переименование
`watcher` → `ignored`, `e` → `ignored`, `scope` → `ignored` — механизм самого правила, честнее,
чем `// NOPMD`-комментарий: имя передаёт намерение, подавление живёт в точке объявления
(проверено фактическим прогоном — находки ушли, новых не появилось).

## Risks / Trade-offs

- [Гейт неиспользуемого кода неполон: формальные параметры не проверяются] → осознанно.
  `UnusedFormalParameter` даёт шум на Spring-обвязке; набор правил расширяется правкой одного
  файла `pmd-ruleset.xml`.
- [`ignored`-префикс скроет настоящий мусор в переименованных переменных] → правило применяется
  точечно к `try`-ресурсам, где ссылка невозможна по построению; настоящий мусор (мёртвые поля,
  лишние импорты, неиспользуемые локальные) по-прежнему виден.
- [findsecbugs на будущем коде даст новые находки безопасности] → это цель гейта; разбор —
  по той же схеме: реальное — починить, намеренное — подавить по месту с обоснованием.
- [Общий `../pmd-ruleset.xml` хрупок при переносе проекта] → репозиторий самодостаточен, все три
  проекта лежат рядом с корнем; это плата за отсутствие третьей копии набора правил, принятая
  как и с остальной конфигурацией стенда.
- [Правки `EtcdConfigWorker`/`MechanismSpans` изменят журналы/трассы] → удаление мёртвого
  параметра значений не меняет; переименования — только имена локальных переменных, на проволоку
  и метрики не влияют (проверяется на стенде).
