# Proposal

## Why

Конфигурация пула появляется в etcd проактивно: разовый сидер кладёт стартовые ключи для
статичного списка инстансов при поднятии стенда. Теперь у каждого инстанса есть собственный узел
регистрации на аренде — появление и исчезновение этого узла это готовый сигнал о жизни инстанса.
Нужно, чтобы конфигурация следовала за жизнью инстанса реактивно: инстанс зарегистрировался —
ключи появились, инстанс остановился — ключи удалены, без статичного списка и без предзаполнения.

## What Changes

- Новый отдельный сервис-провижер (Spring Boot 3.5, jetcd): наблюдает за деревом
  `{root}/services/` и реагирует на события узлов регистрации инстансов.
- Появление узла → в путь инстанса добавляются отсутствующие стартовые ключи `maximumPoolSize`,
  `connectionTimeoutMs`; существующие значения **не перезаписываются** (`put_if_absent`).
- Исчезновение узла (штатная остановка, краш, истечение TTL) → удаляется весь префикс
  `.../{instance}/hikari/` этого инстанса.
- На старте и после каждого обрыва — полная сверка: инвариант «ключи конфигурации существуют
  тогда и только тогда, когда существует узел регистрации» восстанавливается в обе стороны
  (живой узел без ключей — провижин, ключи без узла — удаление).
- Изменение событий конфигурации (`hikari/*`), своих записей и ручных правок оператора провизор
  игнорирует — петель и «борьбы» за ключи нет.
- Разовый сидер `etcd-seed` и цель `make seed` удаляются из стенда; `SEED_*`-переменные
  заменяются на `PROV_*`; у инстансов снимается `depends_on` на завершение сидера.
- **Сервис и его готовность не меняются**: гейт трафика по-прежнему открывается первым
  распознанным ключом, окно «зарегистрирован, но не готов» остаётся нормальным состоянием.

## Capabilities

### New Capabilities

- `config-provisioner`: реактивное провижинирование ключей конфигурации по событиям узлов
  регистрации — появление узла порождает стартовые ключи, исчезновение узла удаляет их, сверка на
  старте и после обрывов держит инвариант «ключи ⟺ живой узел», события конфигурации игнорируются,
  недоступность хранилища переживается с восстановлением.

### Modified Capabilities

- `demo-stand`: требование «Стартовая конфигурация готовится идемпотентно» меняет семантику —
  конфигурация готовится реактивно по факту регистрации инстанса; повторные прогоны не
  перезаписывают существующие значения, **пока узел жив**; исчезновение узла удаляет конфигурацию
  инстанса.

## Impact

- Новый модуль `provisioner/` (Spring Boot 3.5.16, Java 21, jetcd 0.8.7) с собственным Dockerfile
  и композ-сервисом `config-provisioner` (healthcheck по liveness-индикатору).
- `docker-compose.yml`: удаляется сервис `etcd-seed`, добавляется провизор; у инстансов снимается
  зависимость от сидера (порядок старта не влияет на корректность — сверка всё догоняет).
- `Makefile`, `.env.example`, `.env`: удаление `make seed` и переменных `SEED_*`, добавление
  `PROV_*`; цель `make registrations` остаётся (узлы — тот же триггер для наблюдения).
- Документация: README (схема и команды), docs/mechanism.md (раздел провижининга),
  docs/operations.md (переменные, troubleshooting), AGENTS.md (таблица capability, инварианты).
- Спеки: новая capability `config-provisioner`; модификация `demo-stand`.
