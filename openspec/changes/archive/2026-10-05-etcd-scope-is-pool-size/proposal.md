# Proposal

## Why

Конфигурация пула приходит из etcd целиком — одиннадцатью ключами, — хотя провижёр управляет
только `maximumPoolSize`, а остальные десять на стенде не пишет никто: ни провижёр, ни compose,
ни оператор. Часть из них дублирует локальную конфигурацию процесса (`DB_URL`, `DB_USER`,
`DB_PASSWORD`, `POOL_NAME`), часть просто не используется.

Последствия шире лишних строк в разборе ключей:

- **«Целевые» ключи** (`jdbcUrl`, `username`, `password`, `poolName`) — единственный способ сменить
  цель соединения на работающем пуле. Цель не меняется: адрес базы приходит локально из `DB_URL`, и
  это зафиксированное правило проекта (провижёр о базах не знает, в etcd баз нет).
- **Пароль в etcd** — лишняя копия секрета в открытом виде там, где есть локальное окружение.
- **Таймауты** (`connectionTimeoutMs`, `idleTimeoutMs`, `maxLifetimeMs`, `validationTimeoutMs`,
  `leakDetectionThresholdMs`) — единственный путь, которым таймауты меняются на работающем пуле
  через MBean; локально они статичны. `connectionTimeoutMs` вдобавок держит воспроизводимость 503
  перегруза на стенде.

## What Changes

- Конфигурация из etcd остаётся про размер и минимум: `maximumPoolSize` и `minimumIdle`.
  Минимум нужен механизму — без него сжатие не освобождает idle-соединения сразу.
- Целевая часть конфигурации (`jdbcUrl`, `username`, `password`, `poolName`) больше не приходит из
  etcd и берётся только из локальной конфигурации процесса.
- Ключи таймаутов больше не приходят из etcd и остаются локальными настройками.
- Ключ, который больше не входит в перечень распознаваемых, трактуется как опечатка: применяются
  остальные, предупреждение выводится один раз. Смена цели пула с etcd становится недостижимой.

**BREAKING (внешнее поведение):** правка `hikari/jdbcUrl` больше не пересоздаёт пул — ключ
неизвестен, и пул продолжает работать на прежней базе. Требование «Смена целевого соединения
пересоздаёт пул» снимается; сценарий «Пул создан заново» (выход из нулевого размера) сохраняется
и остаётся единственным путём пересоздания.

## Capabilities

### New Capabilities

- Нет.

### Modified Capabilities

- `etcd-config-source`: перечень ключей конфигурации сужается до размера и минимума; ключи вне
  перечня — опечатки.
- `config-validation`: обязательные параметры и диапазоны берутся из локальной конфигурации;
  сняты требования о диапазонах etcd-таймаутов и о невозможных сочетаниях таймаутов.
- `pool-lifecycle`: снимается требование о пересоздании при смене целевого соединения.

## Impact

- `service/`:
  - `etcd/EtcdKeys.java`: перечень распознаваемых ключей сужается до `maximumPoolSize` и
    `minimumIdle`, разбор целевых полей и таймаутов из etcd уходит;
  - `pool/ManagedPool.java`: уходит триггер пересоздания по смене цели, но остаются
    `Outcome.RECREATED`, счётчик `pool.recreate` и дренаж — они нужны выходу из нулевого размера;
  - `etcd/EtcdKeysTest.java`: тесты ключей приводятся в соответствие.
- `provisioner/`:
  - `ProvisioningWorker.java`: стартовый ключ `connectionTimeoutMs` больше не кладётся; остаётся
    только `maximumPoolSize`.
- Плата: смена цели соединения на живом пуле недостижима, `docs/experiments.md` содержит снятый
  сценарий с `jdbcUrl` и пересозданием — его надо пометить как историю или убрать.
- Пароль в etcd перестаёт быть возможен: ключ `password` становится неизвестным и не применяется.
