## 2. Механизм

- [x] 2.1 В `pool/ManagedPool.java` убран триггер пересоздания по смене цели: условие
  `targetChanged || ds == null` стало `ds == null`. `Outcome.RECREATED`, счётчик `pool.recreate`
  и событие трассы `pool.recreate` остались и переехали на оставшуюся ветку; мёртвый `sameTarget()`
  и его тест удалены. Вместе с ними удалён разбор «а если пул всё-таки есть» внутри `create()`:
  все три вызова гарантируют `dataSource == null`, а его `recreateCount` и лог «пересоздан» стали бы
  недостижимыми и врали бы. Проверено на стенде: `pool.recreate` в трассах есть,
  `pool.drain.cause=config_removed`, `pool_recreate_total` растёт.
- [x] 2.2 `HikariSettings` продолжает принимать целевые и таймаутные значения из локальной
  конфигурации. Проверка на стенде: пул создаётся (`HikariCP 'service-a-group-1-1' создан: jdbc=…
  user=app max=25 minIdle=25 connectionTimeout=30000ms`) и обслуживает запросы.
- [x] 2.3 Попутно исправлено расхождение со спекой: счётчик пересозданий до правки рос только на
  смене цели, а требование про нулевой размер требует его роста при возврате из нуля. Теперь
  растёт на оставшемся пути. Правки спеки не понадобилось, зафиксировано в design D2.

## 4. Живая проверка

- [x] 4.1 Стенд поднят: 8 инстансов `ready=UP`, `max=25`, в `hikari/` ровно один ключ
  `maximumPoolSize`, сумма долей 100 на сервис.
- [x] 4.2 Неизвестные ключи: положены `jdbcUrl`, `password`, `connectionTimeoutMs`, `idleTimeoutMs`.
  Каждый дал ровно одно предупреждение «в etcd есть неизвестный ключ …», `pool_generation` остался
  1, `pool_recreate_total` остался 0, `application_name` прежние, сессий 100. То есть ключи вне
  перечня не применяются и пул не пересоздают. Ключи удалены.
- [x] 4.3 503 перегруза: `POOL_CONNECTION_TIMEOUT_MS=1000` + `docker compose up -d`, 40 параллельных

  `{"ok":false,"durationMs":1003,"dbMs":0,"queueWaitMs":0,"error":"CannotGetJdbcConnectionException:
  Failed to obtain JDBC Connection"}`. Значение возвращено на 30000, инстанс перезапущен.
- [x] 4.4 Выход из нулевого размера: `R=0` + `group-2` неактивна → конфигурация снята, гейт 503,
  `readiness: DOWN` с причиной «в пути … нет распознанных ключей», в журнале `старый пул закрывается:
  ждём 1 активных соединений (до PT3S)` и `пул закрыт: размер 25 -> 0, активные соединения
  дренированы`; возврат группы → `HikariCP 'service-a-group-2-2' создан заново после снятия
  конфигурации: max=25 minIdle=25`, `pool_generation` 1 → 2, `pool_recreate_total` 0 → 1. В трассах
  `pool.recreate` и `pool.drain{cause=config_removed, active=1, left=0}`. Стенд возвращён.
- [x] 4.5 `make test`, `make pool`, `make check-instances` (8 инстансов, 0 без рядов), `make targets`
