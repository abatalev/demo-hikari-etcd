# Proposal

## Problem Statement

Сейчас размер пула каждого инстанса — доля бюджета сервиса, и все инстансы сервиса обслуживают
одинаково. Нет способа перевести часть флота в «спящий режим»: сжать группу инстансов до тёплого
резерва или до нуля и вернуть её в обслуживание по команде — при том что группа может пересекать
несколько сервисов.

## Goals

- **Группа — глобальный флот.** Активность задаётся маркером на уровне корня
  `{root}/groups/{group}/active` и влияет на узлы группы во всех сервисах.
- **Резерв неактивного флота.** Переименование сервисных ключей бюджета:
  `maxConnections` → `activeMaxConnections` (N), `minConnections` → `activeMinConnections` (m),
  новый `inactiveMaxConnections` (R).
- **Формула.** Неактивные узлы держат ровно R; активные распределяют `N − R×k` (k — число
  неактивных узлов) по прежнему алгоритму с минимумом m. Сумма по сервису остаётся равной N.
- **Режимы резерва.** R = 0 — холодный флот: неактивные инстансы теряют конфигурацию целиком
  (503, `readiness: DOWN`). R от 1 до верхней границы — тёплый пул: неактивный инстанс готов и
  обслуживает на размере ровно R.
- **Пул сервиса — только из конфигурации.** Локальный дефолт размера пула жёстко `0`,
  `POOL_MAX_SIZE` убирается. Пока конфигурация не получена, пула не существует; «потолок
  защищает не полностью» перестаёт быть правдой.
- **Инвариант «0 из etcd отклоняется» удерживается.** Записанный в etcd `maximumPoolSize=0`
  по-прежнему REJECTED: проверка живёт в источнике конфигурации до применения (1 — минимальный
  размер из хранилища), гейт трафика при этом остаётся открытым.

## Non-Goals

- Миграция старых ключей `maxConnections`/`minConnections` — их значения не переносятся, стенд
  один раз сбрасывается (`make clean && make up`).
- Какие-либо изменения жизненного цикла узлов регистрации, выборов лидера и протокола событий.
- Метрики в prometheus-формате, алерты.
- TLS/аутентификация к etcd.

## Capabilities

- `config-provisioner` — маркер групп, поллинг, формула с резервом, новые сервисные ключи.
- `config-validation` — локальный размер пула 0 допустим; 0 из etcd — отказ конфигурации.
- `etcd-config-source` — отклонение `maximumPoolSize=0` из etcd до применения, гейт остаётся
  открытым.
- `pool-lifecycle` — пул не создаётся на старте (дефолт 0), закрытие при нулевом размере с
  дренажом, воссоздание.
- `demo-stand` — команды активного/резервного бюджета и маркера группы, сброс стенда.
- `traffic-readiness` — холодный флот не готов (503/DOWN), тёплый обслуживает на резерве.

## Scope

Провижер (конфигурация, распределение, маркер), сервис (пул из etcd, ноль), команды стенда,
документация, спеки. Пул-наблюдаемость и регистрация инстансов не меняются.
