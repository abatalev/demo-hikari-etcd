# Proposal

## Why

Сейчас провизор конфигурации — единственная точка отказа: один экземпляр на стенд держит весь
провижининг, и `docs/operations.md` прямо фиксирует ограничение «провижер один на стенд, без
лидер-выбора». Чтобы падение провизора не останавливало подготовку конфигурации, нужен резервный
экземпляр. Чтобы при этом не было двух писателей, работа делится выбором лидера: не глобально,
а **по сервисам** `{root}/services/{service}` — крах лидера одного сервиса не задевает остальные,
а реплики полезно делят нагрузку.

## What Changes

- **Выбор лидера на сервис.** Для каждого живого сервиса `{root}/services/{service}` ровно один
  провизор активен (провижин, очистка, сверка); остальные экземпляры бездействуют.
- **Набор сервисов выводится из дерева.** Провижер сам определяет, за какие сервисы участвовать
  в выборах, из `{root}/services/`: список не конфигурируется, новые сервисы подхватываются без
  рестарта, сервис без живых узлов лидера не имеет («ключи выборов ⟺ живой сервис»).
- **Механика выборов.** Аренда etcd (TTL по умолчанию 10с, keepalive), campaign на каждый живой
  сервис; лидер — по наименьшему `create_revision` ключа; перехват — при исчезновении лидера
  (крах → TTL, штатная остановка → resign сразу); вернувшийся провизор становится follower'ом.
- **Новые настройки провизора:** `PROV_NAME` (имя реплики, значение лидер-ключа),
  `PROV_LEADER_TTL` (дефолт 10с).
- **Compose:** два экземпляра провизора (`config-provisioner-1`, `config-provisioner-2`) через
  якорь; `make leader` показывает, кто ведёт каждый сервис.
- **Ограничение «провижер один на стенд»** из `docs/operations.md` снимается.
- Сервис (`service/`, инстансы, их готовность) **не меняется**.

## Capabilities

### New Capabilities

- Нет новых capabilities: поведение добавляется внутрь существующих.

### Modified Capabilities

- `config-provisioner`: новые требования — ровно один активный провизор на сервис, набор
  сервисов из дерева, перехват лидера и переживание обрывов хранилища при выборах.
- `demo-stand`: новое требование — провизор разворачивается двумя экземплярами, при падении
  активного запасной берёт работу.

## Impact

- `provisioner/`: механика выборов (аренда, campaign/наблюдение, resign при остановке), воркер
  провижининга на поддерево `{root}/services/{service}/`; настройки `PROV_NAME`, `PROV_LEADER_TTL`;
  `stop()` отзывает аренду до закрытия клиента.
- `docker-compose.yml`: `config-provisioner-1/2` через якорь `x-provisioner`; `make up` от
  провизора не зависит (проверено `scripts/wait-ready.sh` — только упоминание в сообщении).
- `Makefile`: таргет `make leader` (etcdctl: первый ключ по каждому сервису).
- `.env.example`/`.env`: `PROV_NAME`, `PROV_LEADER_TTL`.
- Документация: `README.md`, `docs/mechanism.md`, `docs/operations.md`, `AGENTS.md`.
- Зависимости: новые не добавляются — `io.etcd.jetcd.Election` уже в jetcd 0.8.7.
- Сервис `service/` не затрагивается.
