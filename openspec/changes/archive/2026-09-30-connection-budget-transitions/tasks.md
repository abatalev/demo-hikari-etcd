# Tasks

## 1. Наблюдение и инструмент замера потолка

- [x] 1.1 Наблюдение учитывает поколение пула, которое освобождает соединения: при закрытии пул
      убирается из ссылки только после дренажа либо его поколение учитывается при ответе.
      Проверка: на стенде `make pool I=<имя>` во время дренажа показывает ненулевое число
      открытых соединений, а не ноль.
- [x] 1.2 Поколение в ответе наблюдения остаётся различимым, чтобы отличить текущий пул от
      освобождаемого. Проверка: `make pool I=<имя>` содержит оба значения во время дренажа.
- [x] 1.3 Цель `make fleet-sessions`: суммарное число соединений по всем пулам флота из сессий
      postgres, а не только разбивка по `application_name`. Проверка: `make fleet-sessions`
      печатает сумму, совпадающую с суммой строк `make sessions` в установившемся режиме.
- [x] 1.4 Документация наблюдения в `docs/api.md`: что означают числа при дренаже. Проверка:
      описанные поля совпадают с фактическим выводом `/api/pool`.

## 2. Публикация неосвобождённого сжатия

- [x] 2.1 Чистая функция долга: `max(0, удерживаемое − потолок)`, потолок берётся из применённой
      конфигурации. Проверка: юнит-тест на нулевом, положительном и отрицательном исходах,
      включая потолок 0.
- [x] 2.2 Публикация выполняется по событию изменения долга, терминальное значение (долг стал
      нулём) проходит безусловно, промежуточные значения допускают настраиваемый квант или
      ограничение частоты. Проверка: юнит-тест на то, что терминальное значение не фильтруется.
- [x] 2.3 Публикация не выполняется, пока величина не менялась и потолок прежний. Проверка:
      юнит-тест плюс стенд — в установившемся режиме `mod_revision` ключа публикации не растёт
      (10с без изменений), а значение равно нулю. Ключ при этом остаётся: его удаление выглядело бы
      для провижёра как отсутствие отчёта, и место перестало бы раздаваться вовсе.
- [x] 2.4 Запись ключа публикации по аренде узла, рядом с `hikari/`, без дополнительного
      уровня. Проверка: на стенде ключ лежит на одной аренде с узлом регистрации (`etcdctl get -w
      fields --prefix .../instances/`), а ненулевое значение появляется при сжатии.
- [x] 2.5 Грамматика путей на стороне сервиса узнаёт собственный ключ публикации и не считает
      его конфигурацией. Проверка: юнит-тест на разбор ключа; `make config I=<имя>` не содержит
      его и не помечает как неизвестный.
- [x] 2.6 Наблюдение при пересоздании пула считает освобождаемое поколение, иначе долг
      публикуется недостоверным. Проверка: во время смены целевого соединения публикуемый
      долг ненулевой ровно пока старый пул держит соединения.
- [x] 2.7 Документация: ключ публикации и его смысл в `docs/mechanism.md`, чтение в
      `docs/operations.md`. Проверка: описанный путь совпадает с фактическим в etcd.

## 3. Порядок остановки инстанса

- [x] 3.1 При штатной остановке соединения освобождаются до снятия регистрации; снятие
      регистрации выполняется после дренажа, а при превышении таймаута — после принудительного
      закрытия соединений с предупреждением. Проверка: на стенде при остановке инстанса его узел
      виден в `make registrations` до завершения дренажа.
- [x] 3.2 Падение процесса порядок не применяет, поведение не меняется. Проверка: инстанс,
      убитый без штатной остановки, исчезает по истечении аренды, лишних записей провизёра нет.
- [x] 3.3 Документация порядка остановки и его цены в `docs/operations.md`. Проверка: описан
      симптом, по которому видно нарушение порядка.

## 4. Разбор ключа и снимок у провижёра

- [x] 4.1 Грамматика ключей провижёра различает узел, ключи конфигурации, ключ публикации и
      опечатку. Проверка: юнит-тест на разбор каждого вида, включая настоящую опечатку под
      узлом, которая по-прежнему распознаётся как опечатка.
- [x] 4.2 Снимок читает текущее значение `maximumPoolSize` и значение публикации каждого узла.

- [x] 4.3 Событие публикации не обрабатывается как изменение состава инстансов и не порождает

      провизёра нет записей узлов в ответ на публикацию.

## 5. Ограничение роста освобождённым сжатием

- [x] 5.1 Чистая функция допустимого роста: занятое узлом равно `потолок + долг`, рост равен
      неотрицательной части `N − сумма занятого` по узлам сервиса, приказ — `min(доля, потолок +
      рост)`, а выданный рост вычитается из остатка в порядке сортировки полного ключа, чтобы
      одно место не досталось двум. Долг берётся из публикации, а при её отсутствии или
      устаревании берётся худший случай — долг равен потолку. Проверка: юнит-тесты на переходе
      4×25 → 5×20, на тесном бюджете N=50 с двумя инстансами, где второй лишний, на «место
      достаётся одному» и на 20 000 случайных достижимых снимков с проверкой суммы «что флот
      будет держать сразу после прохода».
- [x] 5.2 Обработчик событий разделяет раздачу целевых долей и пересчёт допустимого роста:
      публикация меняет только величину роста и не переписывает доли, которые не изменились.
      Проверка: юнит-тест на разветвление; на стенде после события публикации `make config`
      показывает неизменёнными доли тех инстансов, чьи доли не изменились.
- [x] 5.3 Запись выросших долей, с ограничением по освобождённому сжатию. Проверка: на стенде в
      сценарии rolling 4×25 → 5×20 новый инстанс получает свою долю по мере освобождения места
      сжатыми инстансами, а `make budget` показывает в любой момент сумму долей не выше N.
- [x] 5.4 Повторный пересчёт после потери лидерства даёт тот же результат, поскольку все
      величины выводятся из снимка. Проверка: на стенде `make leader` для смены лидера, затем
      `make budget` — доли те же, ограничение роста то же.
- [x] 5.5 Долг, который не меняется дольше настраиваемого времени, фиксируется в журнале с
      числами, место не перераспределяется. Проверка: на стенде вручную записанный ненулевой
      долг при отсутствии сжатия даёт предупреждение провизёра, а место остаётся незанятым.
- [x] 5.6 Настройка порога предупреждения и настройка фильтрации промежуточных публикаций с
      значением по умолчанию, при котором фильтрация выключена. Проверка: `make config` на
      стенде и запуск юнит-тестов сервиса и провижёра.

## 6. Проверка на стенде

- [x] 6.1 Сценарий rolling 4×25 → 5×20 при N=100: сумма соединений флота по `make
      fleet-sessions` не превышает 100 ни в один момент перехода. Проверка: замер снимается
      непрерывно во время перехода, а не только в установившемся режиме.
- [x] 6.2 Сценарий деактивации группы 4×25 → 20/20/30/30: сумма не превышает 100. Проверка:
      `make set-group-active G=group-2 ACTIVE=false` под непрерывным замером.
- [x] 6.3 Сценарий изъятия доли 4×25 → 34/33/33/0: сумма не превышает 100. Проверка: тот же
      непрерывный замер на тесном бюджете.
- [x] 6.4 Сценарий штатной остановки: место освобождается один раз, сумма не превышает N.
      Проверка: `make service-restart P=<имя>` под непрерывным замером плюс порядок из 3.1.
- [x] 6.5 Сценарий падения инстанса без штатной остановки: сумма не превышает N, лишних записей
      провизёра нет. Проверка: `docker compose kill` инстанса под непрерывным замером.
- [x] 6.6 Отсутствие свежей публикации не ломает работу: инстанс без отчёта (только что поднялся
      или перезапущен, а также старая версия сервиса) учитывается по худшему случаю, флот работает
      меньше бюджета и место не выдаётся никому. Отдельного выключателя публикации нет, поэтому
      сценарий воспроизводится инстансом без отчёта. Проверка: `docker compose restart`
      service-a-group-1-1` под непрерывным замером перехода — пик ≤ N, `make fleet-sessions`
      показывает худший случай выше отчёта и OK/ПРЕВЫШЕНИЕ = OK.
- [x] 6.7 Замеры записаны в `docs/experiments.md` вместе с числами до и после изменения, чтобы
      виден был эффект. Проверка: в документе есть обе колонки и сценарии 6.1–6.5.
